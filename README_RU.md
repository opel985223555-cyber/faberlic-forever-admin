# Faberlic Forever — учёт и групповая выдача промокодов

Обновление 25.10.2026. В этом ZIP полный сайт админки. Android/iOS менять для этой функции не нужно: последние приложения совместимы.

## Установка

1. Скопируйте текущие правила Firebase для собственной резервной копии. В Firestore → Rules полностью вставьте FIRESTORE_RULES_UPDATED.txt из ЭТОГО архива и нажмите Publish самостоятельно. Файл идентичен firestore.rules. Добавлена закрытая коллекция promoDistribution; без новых правил раздел промокодов не сможет прочитать историю выдач. Anonymous и вход администратора остаются как ранее настроены.
2. Обновите файлы админки на GitHub с сохранением папок, дождитесь deployment GitHub Pages и обновите страницу Ctrl+F5. На телефоне обновите/перезагрузите страницу. Для изменённых файлов установлена новая метка кэша distribution16.
3. Откройте «Промокоды», нажмите «Обновить». Счётчики показаны вверху. Для первой проверки используйте несколько кодов в тестовом Firebase-проекте, а не генерацию 5000 в рабочем.

Ничего автоматически не опубликовано, production Firebase и main агент не менял. Реальные коды не созданы и не выданы.

## Счётчики

* Создано — все одноразовые коды, включая заблокированные/использованные.
* Выдано — отмеченные выданными плюс уже активированные коды. Активированные старые коды учитываются как фактически переданные, даже если ранее отдельного учёта выдачи не было.
* Осталось для выдачи — свободные, включённые, ещё не отмеченные выданными.
* Активировано — использованные одноразовые коды.
* Выдано, ждут активации — отмеченные выданными, но ещё не активированные (включая временно заблокированные).
* Заблокировано — одноразовые коды с выключенным доступом; этот показатель может пересекаться с другими статусами.

Универсальный код не входит в эти числа. Чтобы увидеть новые активации или изменения другого администратора, нажмите «Обновить». Отправку и получение сообщения в Telegram админка не проверяет: «выдано» означает вашу отметку о передаче/подготовке кодов.

Ранее переданные, но ещё не активированные коды невозможно определить автоматически. Один раз отметьте их выданными через выбор кодов и кнопку выдачи. Использованные коды уже включаются в «Выдано» автоматически.

## Выдать пять кодов одному человеку для дальнейшей раздачи

1. Укажите 5 и нажмите «Генерировать», подтвердите количество в окне по центру.
2. После генерации эти пять автоматически выбраны. Прокрутите к блоку «Выдать группу кодов» и нажмите «Выдать и скопировать: 5», подтвердите.
3. Админка одной транзакцией сохранит выдачу, затем скопирует пять кодов: каждый на отдельной строке.
4. Откройте Telegram, выберите человека, вставьте список и отправьте сами. Он сможет выдать людям по одному коду. Никакой автоматической рассылки или обращения к Telegram API нет.

Вы можете выбирать существующие коды галочками; «Выбрать свободные» выбирает до 10 кодов. Одна выдача — от 1 до 10 кодов, чтобы сохранить атомарность и уложиться в ограничения Firestore Rules. Генерация по-прежнему поддерживает до 5000.

Выдача НЕ активирует коды. После выдачи пяти кодов «Выдано» увеличится на пять; «Активировано» увеличится только при вводе людьми на устройствах. Ограничение «одна установка на одноразовый код» сохраняется.

## Одиночная выдача, повторное копирование и сбои

Для нового кода кнопка «Выдать / скопировать» отмечает выдачу и копирует код. Для уже выданного — «Скопировать» без повторного увеличения счётчика. Универсальный код копируется отдельно, без учёта в одноразовых выдачах.

Внизу есть «Выданные группы»: количество, дата и число активированных кодов внутри каждой группы. «Скопировать группу» повторно копирует тот же список и не меняет счётчики. История хранится в Firebase и доступна после перезапуска/на другом устройстве администратора. CSV для Excel дополнен группой и датой выдачи; храните экспорт закрыто.

Если копирование запрещено браузером, выдача остаётся сохранённой. Нажмите «Скопировать группу» ещё раз; не создавайте новую выдачу. При сетевой ошибке обновите список перед повторным действием: сохранённая группа будет видна, даже если ответ сервера был потерян.

Выданный код нельзя повторно выдать другой группой. Два администратора не смогут одновременно выдать один код. Использованные, заблокированные и универсальные коды не принимаются как новая одноразовая выдача. Частично недопустимая группа не сохраняется. История выдачи неизменяема; копирование безопасно повторять.
