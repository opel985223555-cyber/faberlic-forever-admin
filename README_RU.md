# Faberlic Forever — обновление Android, iOS и админки

Дата комплекта: 25 октября 2026. Версия мобильных приложений 1.1.0, номер сборки 20.
Это полные исходные проекты. Подписанные APK/AAB/IPA в комплект не входят. Ничего не опубликовано в GitHub/Firebase, рабочая база и main не изменены, реальные промокоды не созданы.

## Какие архивы использовать

* `Faberlic_Forever_Android_UPDATED.zip` — только Android Studio проект.
* `Faberlic_Forever_iOS_Xcode_UPDATED.zip` — только Xcode проект.
* `Faberlic_Forever_Admin_UPDATED.zip` — только сайт админки, правила Firestore и страница удаления аккаунта.

Распакуйте каждый ZIP в отдельную папку. В каждом архиве исходники лежат сразу в корне. Android и iOS файлы на GitHub Pages админки загружать не нужно. Старые инструкции CMS-07/08/10 в исходниках — исторические; для этого обновления используйте данный README.

## Что изменено

В мобильных приложениях четыре пункта: Главная, Категории, Материалы, О приложении. На главной баннер, поиск, история и новинки; горизонтальные фильтры категорий убраны. Баннер содержит до 10 последних опубликованных уроков текущего языка в порядке от старого к новому, новинки — те же уроки от нового к старому, две колонки. Поиск работает по всей доступной опубликованной библиотеке текущего языка. Старые уроки остаются в категориях.

История хранит реально открытые уроки локально, повторное открытие поднимает урок вверх. Точная позиция воспроизведения не восстанавливается. Поиск сохраняет текст и результаты при закрытии клавиатуры. Сохранены RU/TJ/UZ, плеер, материалы, вложенные категории и существующий стиль. Удаление вкладок не удаляет записи эфиров или сохранённое избранное; явная команда удаления аккаунта очищает личные локальные данные.

Добавлены экран приглашения, серверная одноразовая активация Android/iOS, универсальный код, блокировка установок и удаление аккаунта. До активации подписки на закрытый контент не запускаются; правила также запрещают его чтение. Доступ подтверждается сервером, для активации и проверки нужен интернет; офлайн-доступ не обещается. В native-приложении сохраняется анонимная сессия Firebase, а не открытый код в JavaScript.

Админка основана на GitHub commit `bb02923f0f6af674eae5aae78a06b8c59e09181a` от 24.10.2026. Сохранены удаление пустых категорий, защита уроков и вложений, скрытие/техническое закрытие, красная индикация и исправление сравнения объектов при другом порядке полей. Добавлены «Промокоды», поиск/фильтры, CSV для Excel и блок универсального кода. Пункт «Эфиры» убран, документы эфиров сохранены.

Новое `publishedAt` фиксирует первую публикацию. Повторная публикация и ручная сортировка дату не меняют. Для ранее опубликованных уроков без этой даты используется `createdAt`: точную историческую первую публикацию восстановить из старых данных невозможно. Остальные разделы сохраняют ручной порядок.

## Порядок обновления Firebase и сайта

1. Сделайте собственную резервную копию исходников и Firestore. Согласуйте запуск новых приложений и правил: старые приложения без активации после новых правил потеряют чтение контента.
2. В том же Firebase-проекте откройте Authentication → Sign-in method и включите **Anonymous**. Вход администратора и существующий документ `admins/<UID>` с `active: true` оставьте. Не включайте автоматическое удаление анонимных аккаунтов старше 30 дней: это может лишить выданного доступа постоянных пользователей.
3. Откройте Firestore Database → Rules. Полностью замените текст содержимым **firestore.rules** из нового архива админки и нажмите Publish самостоятельно. `FIRESTORE_RULES_UPDATED.txt` содержит точно тот же текст для копирования. Это одни правила для обеих платформ и админки. Не добавляйте `allow write: if true`.
4. В репозитории сайта создайте собственную ветку, замените файлы из архива **админки** с сохранением путей: в частности index.html, assets/, config/, firestore.rules и account-deletion.html. Полный исходный сайт уже есть в архиве; смешивать его с папками Android/iOS не нужно. Сравните изменения, затем публикуйте выбранным вами способом. В main агент ничего не менял.
5. Дождитесь завершения GitHub Pages deployment, выполните Ctrl+F5 и войдите администратором. Проверьте «Категории», «Промокоды» и адрес `/faberlic-forever-admin/account-deletion.html`. Страница удаления станет доступна только после вашей публикации.
6. На копии/тестовом Firebase сначала проверьте активацию и категорию с уроком. При первом обслуживании старого каталога админ инициализирует счётчики связей под контролем общей ревизии; не меняйте эти служебные документы вручную. Для конкурентной безопасности все изменения уроков выполняйте через обновлённую админку.

Cloud Functions и платный Blaze для этой реализации не требуются. Квоты Firebase Spark всё равно действуют. Генерация 5000 кодов создаёт свыше 10000 документов; считайте дневные квоты чтения/записи перед запуском и не генерируйте повторно без необходимости.

## Промокоды

Реальные 5000 кодов **не сгенерированы**. После проверки владелец сам открывает «Промокоды», задаёт количество до 5000 и подтверждает создание. Это отдельное подтверждение в интерфейсе. Пакеты по 200 кодов сохраняют серверную контрольную точку. При ошибке повторите действие в той же вкладке: сохранённая задача продолжится без повторной выдачи уже записанного пакета. Если вкладка закрыта и sessionStorage утрачен, сначала обновите список и посчитайте уже созданные коды, затем создавайте только недостающее количество.

Одноразовый код общий для Android и iOS: одновременная попытка двух устройств завершится одной успешной активацией. ID установки — случайный анонимный UID и случайная метка приложения, без IMEI/Android ID/IDFA. Новое устройство, переустановка с удалением данных или удаление аккаунта требуют нового одноразового кода. Перезапуск установленного приложения сохраняет доступ при успешной серверной проверке.

Универсальный код создайте в отдельном блоке самостоятельно. В архиве его нет. Он проверяется сервером и не встроен в приложение. Его можно блокировать/заменять; замена отзывает доступ установок, активированных старым универсальным кодом. Для перехода на новый код выполните «Сбросить активацию» нужного устройства в админке и введите новый код в приложении. Не вращайте код во время проверки магазина. Не раздавайте его участникам вместо одноразовых кодов.

CSV экспорт содержит коды и статусы, открывается в Excel (UTF-8 BOM, разделитель `;`). Храните файл закрыто. Список установок позволяет отключить конкретный UID. Plaintext-коды доступны только администратору в `promoSecrets`; публичный клиент знает лишь хеш введённого кода и не может выгрузить список.

## Android Studio и AAB

Откройте папку Android (в ней settings.gradle и app/) в Android Studio. Используйте JDK 21 и установленный Android SDK 35, интернет для Gradle зависимостей. Gradle wrapper 8.9 включён с проверкой SHA-256. `app/google-services.json` сохранён из исходного Android-проекта: убедитесь, что он от вашего Firebase-проекта и приложения `tj.faberlic.forever`. Для другого тестового проекта скачайте соответствующий конфиг и используйте тестовую админку/правила.

Из корня Android: `./gradlew :app:assembleDebug :app:bundleRelease` (Windows: `gradlew.bat`). Release AAB без настройки signing будет **неподписанным**. Для магазина: Build → Generate Signed Bundle / APK → Android App Bundle, выберите собственный keystore, Release. Ключи подписи в комплекте отсутствуют. Если в Play уже есть более высокий versionCode, увеличьте 20 до свободного значения. Не меняйте существующий applicationId и ключ подписи опубликованного приложения.

## Xcode и iOS

Нужны macOS, совместимый Xcode и Apple Developer Team. Откройте `FaberlicForever.xcodeproj`, дождитесь Swift Package Manager (FirebaseCore/Firestore/Auth), выберите Team в Signing & Capabilities и своё устройство/симулятор.

**В исходном ZIP не было настоящего GoogleService-Info.plist.** В Firebase зарегистрируйте/выберите iOS-приложение с bundle ID `tj.faberlic.forever`, скачайте его конфигурацию и поместите именно `FaberlicForever/GoogleService-Info.plist` (ссылка ресурса уже добавлена в проект). Файл `.example` не даёт подключения и не заменяет настоящий plist. У iOS и Android должны быть конфигурации одного Firebase-проекта.

Проверьте Build 20/Version 1.1.0, Info.plist, Bundle ID, App Icon. Сначала Build и запуск на iPhone, затем Product → Archive → Distribute App по вашему типу распространения. Подпись и App Store Connect выполняет владелец. На Windows native iOS не компилировался; синтаксические проверки ресурсов не заменяют Xcode.

## Удаление аккаунта и конфиденциальность

Кнопка есть в «О приложении» и на экране активации, подтверждение локализовано. Она очищает локальную историю/избранное, удаляет запись доступа установки, связь с использованным кодом и анонимного пользователя Firebase Auth. При сетевой ошибке повторите удаление: частично завершённое удаление Auth восстанавливается при следующем запуске. До завершения повторная активация блокируется. Использованный код остаётся использованным без UID удалённого аккаунта.

В Google Play укажите внешний URL удаления после публикации страницы: `https://opel985223555-cyber.github.io/faberlic-forever-admin/account-deletion.html`. Запросы через email владелец обрабатывает вручную: подтвердить принадлежность по ID/ранее выданному коду, удалить installations/UID и принадлежащий ему promoClaims/HASH, затем Authentication пользователя UID. Не переводить использованный код обратно в free. На недоступном устройстве удалённо локальную историю очистить нельзя; пользователь очищает данные/удаляет приложение. Обновите опубликованную политику конфиденциальности под анонимную идентификацию, коды, удаление и Firebase; её текст в этом комплекте не публиковался.

Firestore защищает каталог и метаданные. Публичные YouTube/PDF URL не являются DRM и при известной прямой ссылке могут открываться вне приложения.

## Проверка Apple/Google и тестовый доступ

Платежи не добавлены. Модель — закрытое обучение команды по приглашению. До отправки заполните App Privacy / Data Safety согласно фактическим SDK и настройкам; выберите подходящий вариант распространения для своей аудитории. Доступ по приглашению сам по себе не гарантирует одобрения магазина.

В Review Notes / App access укажите рабочий универсальный код, точные шаги «запустить → ввести код → Активировать», контакт владельца и описание закрытого обучения. Оставьте тестовые уроки/материалы доступными и код включённым на весь срок проверки. Проверяющий должен получить полный доступ без обращения к владельцу.

Официальные требования: [Apple Review Guidelines](https://developer.apple.com/app-store/review/guidelines/), [удаление аккаунта Apple](https://developer.apple.com/support/offering-account-deletion-in-your-app/), [Google Play: удаление аккаунта в приложении и через внешний ресурс](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en). Firebase: [анонимный вход Android](https://firebase.google.com/docs/auth/android/anonymous-auth), [iOS](https://firebase.google.com/docs/auth/ios/anonymous-auth), [атомарные проверки getAfter](https://firebase.google.com/docs/firestore/security/rules-conditions).
