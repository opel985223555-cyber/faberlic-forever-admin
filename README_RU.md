# Версия 0.4 — параметры Firebase Web подключены

Конфигурация Web App из Firebase Console внесена в `config/firebase-config.js`. Учётные данные Firebase Auth (email/пароль) вводятся только в форме входа и НЕ входят в архив. UID администратора НЕ хранится в сайте: права определяет Firestore-коллекция `admins`. Важное ограничение: вход и запись уроков не проверены на опубликованном HTTPS-сайте. Перед использованием проверьте подлинность значений в `config/firebase-config.js` по Firebase Console (особенно `apiKey`).

# Faberlic Forever — веб-админ-панель, релиз-кандидат 0.3

Сайт подготовлен для GitHub Pages. Он НЕ содержит демонстрационного входа. Публиковать на рабочий адрес следует **после** настройки Firebase и проверки правил доступа. Дизайн 0.2, фирменный 3D-логотип и модульная структура сохранены. Android-приложение НЕ менялось.

## Что работает в интерфейсе
- Видеоуроки: добавить YouTube-ссылку, категорию, подраздел/статус, язык RU/TJ/UZ, ориентацию 9:16/16:9, описание, порядок, статус «Черновик/Опубликовано».
- Редактирование, удаление, поиск, фильтры и счётчики уроков.
- Отдельные разделы: Обзор, Видеоуроки, Категории, Обучение по статусам 3–23%, Эфиры, Материалы, Настройки. Эфиры и Материалы пока оформлены как самостоятельные заглушки без редактирования содержимого.
- Настоящая запись уроков предусмотрена через Firestore, но **не проверена на реальном проекте** до подключения Firebase.

## Следующий этап: Firebase, прежде чем загружать сайт на GitHub
1. Войти в https://console.firebase.google.com/ → существующий Firebase-проект `faberlic-forever`.
2. На странице настроек проекта добавить **Web app** (символ `</>`), имя `Faberlic Forever Admin`; не создавать новый Firebase-проект. Firebase Hosting для GitHub Pages не нужен.
3. Параметры `firebaseConfig` уже внесены в `config/firebase-config.js` по скриншоту веб-регистрации. Сверьте их с Firebase Console при публикации. Это клиентские настройки, не секретный ключ. **Не вставлять** Android `google-services.json` и никогда не добавлять `serviceAccountKey.json` или пароль.
4. Firebase Authentication → Sign-in method → Email/Password → Enable. В Users → Add user создать администратора с личным email и надёжным паролем.
5. Firestore Database → Create database, в режиме production → вкладка Rules → вставить `firestore.rules` из этого архива → Publish.
6. Firestore → Data → коллекция `admins` → документ с ID, в точности равным UID из Authentication → Users → поле `active` (boolean) = true. Админ-панель пропустит лишь пользователя с этой записью. **Не создавать `admins` с произвольным ID или с email вместо UID.**
7. Проверить вход, создание/редактирование/удаление черновика и публикацию; проверить, что неавторизованный пользователь не может изменить данные. Эту проверку нужно провести на реальном Firebase.
8. GitHub → новый отдельный репозиторий `faberlic-forever-admin` → загрузить содержимое распакованной папки (index.html в корне), а не сам ZIP → Settings → Pages → Deploy from branch → main /root → Save. Адрес обычно `https://USERNAME.github.io/faberlic-forever-admin/`.
9. Firebase Authentication → Settings → Authorized domains → при необходимости добавить именно `USERNAME.github.io` без `https://` и без пути репозитория.
10. После проверки сайта **отдельной задачей** подключить Android-приложение к чтению `lessons` из Firestore. Сейчас новая админ-панель сама по себе не публикует уроки в установленное Android-приложение.

## Модульная защита
- `assets/js/modules/videos.js` — только видеоуроки; `categories.js` — категории; `ranks.js` — статусы; `live.js` — эфиры; `materials.js` — материалы; `overview.js` — обзор; `settings.js` — настройки.
- `assets/js/core/*` — общие авторизация, данные и навигация; `assets/css/branding.css` — фирменный стиль и логотип; `assets/css/base.css` — общий каркас.
- `LOCKED_MODULES.json` и `tests/verify_module_lock.py` фиксируют контрольные суммы рабочих файлов. Изменять только согласованные модули, затем проверять все остальные.

## Безопасность и ограничения
GitHub Pages делает исходный код интерфейса общедоступным, но Firebase Security Rules ограничивают чтение черновиков и любые изменения. Никогда не помещайте в репозиторий пароли и приватные ключи. Файлы `firestore.rules` ещё должны быть реально применены в консоли Firebase. По умолчанию приложение заблокировано без веб-конфигурации Firebase. Для Gotham Pro нужен соответствующий лицензированный веб-шрифт; его файл в архив не включён.
