# Faberlic Forever — автономный Splash Preview

Самостоятельный прототип. Приложение v0.9 не подключено и не изменено.

## Запуск на телефоне

1. Скопируйте или скачайте `splash-preview.html` на Android.
2. Откройте файл в браузере, который разрешает открывать локальные HTML-файлы, либо в тестовом Android WebView. Некоторые файловые менеджеры показывают HTML как текст: в таком случае выберите «Открыть с помощью» браузера/WebView viewer.
3. Нажмите «Повторить анимацию» для повторного просмотра. Общая длительность — 6,3 секунды. Этапы идут строго последовательно: рамка, F, Play, плавное появление названия за 1,2 секунды, пауза для чтения на 3,5 секунды, исчезновение. Между этапами нет дополнительного ожидания. Старт запускается сразу после разбора HTML, без отдельного ожидания предварительной загрузки PNG. Интернет не нужен: CSS, JavaScript и исходный PNG встроены в HTML. Копия этого же автономного HTML находится в соседней папке outputs под именем `Faberlic-Forever.html`.

На компьютере достаточно открыть этот HTML двойным щелчком. Для разработки откройте `index.html` рядом с `splash.css` и `splash.js`.

## Файлы

- `splash-preview.html` — автономная версия со всеми ресурсами внутри.
- `splash-app.html` — та же анимация без тестовой кнопки, статуса и служебного заголовка. Готовая копия находится в outputs под именем `Faberlic-Forever-app.html`; все ресурсы встроены. После окончания она отправляет `faberlic:splash-complete`, но самостоятельно не открывает главный экран: переход подключается в приложении отдельно.
- `index.html`, `splash.css`, `splash.js` — версия с отдельными файлами для редактирования; PNG также встроен в index.html.
- `logo.png` — исходное изображение без изменения байтов, пропорций, цвета и прозрачности.
- `preview.png` — кадр готового прототипа.

SVG clipPath разделяет отображение одного исходного PNG на рамку, область F и Play. Это маски областей, а не новая векторная версия логотипа. В конце появления области составляют исходную картинку. Форма F и Play не перерисована. Чёрный фон PNG сохранён; дополнительная непрозрачная чёрная подложка остаётся внутри иконки во время появления слоёв. Свечение и объём взяты из исходника. Добавлены только умеренная подсветка Play и мягкий блик.

## Сценарий, 6300 мс

| Время | Действие |
| --- | --- |
| 0–200 мс | Проявление рамки; начальная видимость 20%, без чёрной паузы |
| 200–900 мс | Плавное появление F, масштаб 0,965 → 1, небольшой сдвиг |
| 900–1200 мс | Появление Play, его подсветка и блик |
| 1200–2400 мс | Медленное плавное появление белого названия и тонкого зелёного акцента |
| 2400–5900 мс | Логотип и название неподвижно остаются видимыми для чтения: 3,5 секунды |
| 5900–6300 мс | Плавное исчезновение композиции |

После исчезновения остаётся #090A0C и тестовые элементы просмотра. Главный экран приложения здесь не имитируется.

При системном `prefers-reduced-motion: reduce` логотип и название отображаются сразу, масштабирование, сдвиг и блик отключаются; остаётся мягкое исчезновение в конце 6,3 секунды. Нет циклической анимации, звука, вращения, вспышек или тряски. Длительность считается с запуска скрипта после разбора HTML, без искусственной паузы. Чтение файла и декодирование PNG зависят от устройства; при будущей интеграции документ лучше подготовить до показа WebView. Шрифт — локальный системный, без загрузки из сети.

## Проверка и производительность

Прототип визуально проверен в настольном браузере: ранняя фаза F, итоговый логотип, название, повтор и завершение. Ошибок загрузки логотипа не обнаружено. Анимации используют преимущественно opacity и transform, без покадрового JavaScript, анимируемых blur-фильтров или внешних библиотек. Цель — 60 FPS; фактическую частоту, работу reduced motion и поддержку локального HTML необходимо проверить на целевых телефонах и в их Android WebView. Настольный просмотр не подтверждает 60 FPS на Android.

## Будущая интеграция — только после утверждения

1. Хранить заставку отдельным модулем `splash-preview`, с локальными ресурсами. Удалить из версии для приложения только тестовые `.preview-label`, `.controls` и связанные элементы управления; сохранить анимацию и её стили.
2. Показать её в отдельном временном WebView поверх стартующего существующего главного экрана. Присвоить контейнеру цвет #090A0C, чтобы до загрузки не возникала белая вспышка. Запретить внешние переходы и сетевые ресурсы для этого локального экрана.
3. Подготовить существующий главный экран под заставкой, без изменения его разметки, темы, шрифтов, цветов, меню, навигации и функций.
4. Использовать событие `faberlic:splash-complete` после завершения CSS-анимации. В будущем Android-адаптер может передать этот сигнал через ограниченный мост для доверенного локального документа и убрать временный WebView. Сейчас мост и Android-код отсутствуют.
5. Убирать временный экран после сигнала и готовности существующего главного экрана. Предусмотреть ограниченный резервный таймаут и обработку ошибки загрузки, чтобы приложение не зависело от заставки. Длительность ожидания загрузки приложения обсуждается отдельно.
6. Проверить холодный старт, повторное открытие, поворот экрана, возврат из фона, reduced motion, отсутствие белых кадров и производительность на реальных устройствах. Системная заставка Android и переход к ней согласуются отдельно при интеграции.

Публичный API прототипа: `window.FaberlicSplash.replay()` и `window.FaberlicSplash.duration` (6300). Событие `faberlic:splash-complete` содержит `detail.duration` (6300) и `detail.sequence`. Оно сообщает только о завершении визуальной анимации. Удаление тестовых элементов управления не меняет длительность.

Никаких изменений Android-приложения на этом этапе не выполнено.
