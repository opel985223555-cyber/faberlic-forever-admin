25 октября 2026

В этом ZIP только полный сайт админки. Android и iOS сюда загружать не нужно. Последние мобильные архивы с кнопками RU / TJ / UZ уже содержат экран активации и native-проверку кода; для этой доработки админки их пересобирать не требуется.

1. Замените файлы сайта админки на GitHub содержимым этого архива, сохраняя пути папок. Ничего автоматически не опубликовано. Если используете ветки — сначала проверьте в своей ветке. После публикации GitHub Pages дождитесь deployment и обновите страницу Ctrl+F5.

2. Firebase Console → Authentication → Sign-in method: включите Anonymous. Администратор продолжает входить прежним способом, admins/<UID>.active должен оставаться true. Не включайте автоматическую очистку старых анонимных аккаунтов, если вы хотите сохранять выданный доступ.

3. Firestore Database → Rules: полностью вставьте содержимое FIRESTORE_RULES_UPDATED.txt из этого ZIP и нажмите Publish самостоятельно. Оно совпадает с firestore.rules. Если вы уже публиковали правила из предыдущего полного UPDATED-комплекта, правила не изменились. Нельзя использовать старые CMS-10/13 rules или открывать всем запись.

Внимание: новые правила требуют активации для чтения уроков/каталога/материалов. Старые приложения без активации не смогут читать контент. Перед публикацией правил согласуйте переход пользователей на последние приложения. Проверки сначала выполняйте в тестовом Firebase-проекте с соответствующими конфигурациями всех трёх проектов.

4. В админке откройте «Промокоды». Для первичной проверки создайте 2–3 кода, а не сразу 5000. В рабочей базе даже тестовый код создаётся только после вашего подтверждения в интерфейсе. Введите один в Android, проверьте повторный запуск. Попытка использовать его на другой установке должна показать «Этот код уже использован».

5. После проверки вы можете указать 5000 и подтвердить создание. Реальные 5000 кодов агент не генерировал. Генерация идёт пакетами по 200; при обрыве повторите действие в той же вкладке, чтобы продолжить без дубликатов. Если вкладка/данные сеанса утрачены, сначала посмотрите, сколько кодов уже записалось, и создавайте только остаток. Учитывайте квоты Firebase Spark: 5000 кодов создают свыше 10000 документов.

6. Список кодов: поиск, фильтры «Все / Свободные / Использованные / Заблокированные», дата создания и активации, блокировка/разблокировка, экспорт CSV для Excel. CSV содержит секретные коды — храните его закрыто и выдавайте людям по одному коду. Формат файла UTF-8 BOM, разделитель точка с запятой.

7. «Универсальный — безлимитный»: создайте код отдельной кнопкой. Его нет в исходниках. Он подходит владельцу и проверяющим магазинов на нескольких устройствах. Замена/отключение отзывает доступ устройств, использовавших прежний универсальный код; одноразовые активации не затрагиваются. Во время модерации магазина не отключайте выданный проверяющим код.

8. «Активированные установки»: блокировка временно прекращает доступ, разблокировка восстанавливает его при действующем коде. «Сбросить активацию» с подтверждением удаляет только запись доступа этой установки и её связь с одноразовым кодом. Анонимный Auth-пользователь, история и избранное не удаляются; использованный одноразовый код остаётся использованным. После сброса пользователь может ввести новый одноразовый или текущий универсальный код. Это подходит и для устройств со старым отключённым универсальным кодом.

БЕЗОПАСНОСТЬ И ПРОВЕРКИ
Список кодов, открытый текст кодов, генерация, CSV и управление доступны только администратору. Активация атомарна, одноразовый код нельзя одновременно применить на двух установках Android/iOS. Код не проверяется простым JavaScript-флагом: Firestore правила проверяют серверную транзакцию. Нет IMEI/Android ID/IDFA. Нужен интернет.

Пройдено 46/46 браузерных сценариев админки с поддельным SDK и 18/18 групп правил доступа в локальном Firestore Emulator, включая повторное использование, гонку двух платформ, блокировки, универсальный код и сброс с новой активацией. Генерация 5000 проверена на поддельном сервере; реальный пакет из 200 — локальным эмулятором. Результаты и исходники тестов находятся в verification/. Native активация на физических Android/iPhone пока не проверена; iOS требует сборки на Mac с настоящим GoogleService-Info.plist.

В production ничего не записывалось, main не менялась, Firebase/GitHub не публиковались. Мобильный интерфейс удаления аккаунта остаётся убранным по вашему запросу; требования магазинов к удалению аккаунта нужно согласовать отдельно перед отправкой на модерацию.
