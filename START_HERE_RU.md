# Faberlic Forever — начните отсюда

Обновление от 28.10.2026. Android и iOS: **1.2.0, сборка 22**. Это исходные проекты, без установочных APK, AAB, IPA и ключей подписи.

## Что куда загружать

В общем ZIP находятся три разных проекта:

| Папка | Назначение |
|---|---|
| `1_ADMIN_UPLOAD` | Содержимое этой папки заменяет файлы существующей веб-админки на GitHub. |
| `2_ANDROID_PROJECT` | Полный проект для Android Studio. На GitHub Pages его загружать не нужно. |
| `3_IOS_XCODE_PROJECT` | Полный проект для Xcode на Mac. На GitHub Pages его загружать не нужно. |
| `4_FIREBASE_RULES` | Полные правила Firestore и diff для проверки изменений. |
| `5_VERIFICATION` | Тесты для разработчика. Для обновления сайта эта папка не нужна. |

1. Сохраните резервную копию текущей админки и опубликованных правил Firebase.
2. В своём репозитории [faberlic-forever-admin](https://github.com/opel985223555-cyber/faberlic-forever-admin) замените **содержимое** папки `1_ADMIN_UPLOAD`, сохраняя пути `assets`, `config`, `index.html`. Не создавайте на сайте дополнительную папку `1_ADMIN_UPLOAD`.
3. Сохраните собственную конфигурацию `config/firebase-config.js`, если меняли её после предыдущей версии.
4. Примените правила по инструкции ниже. После завершения GitHub Pages deployment обновите админку с Ctrl+F5. Скачивание ZIP само по себе сайт не обновляет.

Ничего не опубликовано автоматически; ветка main и рабочие записи Firebase агентом не изменялись.

## Что сделать в Firebase

1. Откройте Firebase Console → свой существующий проект Faberlic Forever.
2. Перейдите в **Firestore Database → Rules** (не Storage и не Realtime Database).
3. Сохраните текущий текст отдельно. Сравните его с `4_FIREBASE_RULES/firestore.rules`. Если в Console есть ваши более поздние изменения, сначала совместите их; не затирайте их вслепую.
4. Для показанного в этой работе исходного проекта используйте **полный текст** `4_FIREBASE_RULES/FIRESTORE_RULES_UPDATED.txt`: выделите всё в редакторе Rules и вставьте этот текст. `.patch` предназначен для просмотра разницы, а не для вставки в Console.
5. Проверьте отсутствие ошибок редактора и сами нажмите **Publish**. До публикации новые записи материалов могут получать permission-denied.

Правила оставляют проверку администратора через `admins/{uid}.active` и существующее серверное право доступа по промокоду. Anonymous Authentication не делает человека администратором. Включать новые методы входа, открывать запись всем или менять действующие промокоды для этого обновления не требуется.

Новые коллекции не надо создавать вручную: первая категория создаёт документ в `materialCategories`, а материал — документ в существующей `materials`. Старые материалы не переносятся и не удаляются.

**Индексы:** новые запросы используют только `where(status == published)`. Достаточно обычной автоматической индексации поля `status` в `materials` и `materialCategories`; составные индексы не добавлялись. Если ранее специально исключили это поле из индексации, верните его одиночный индекс. Не заменяйте существующие индексы пустым файлом.

## Как добавить материалы

1. На Google или Яндекс Диске откройте доступ по ссылке к **отдельному файлу** и разрешите скачивание. Папки, корпоративные закрытые ссылки и Google Docs без экспорта не поддерживаются как документы PDF/DOCX.
2. В админке откройте «Материалы». Создайте категорию: название RU, необязательные TJ/UZ и описания, иконка, порядок, статус.
3. Добавьте документ: название RU, переводы, категория, страна, публичная ссылка, формат, порядок, статус. Источник распознаётся автоматически. Пустые переводы используют RU.
4. Для PPT/PPTX или DOC/DOCX при необходимости добавьте отдельную PDF-копию для просмотра. Оригинал останется доступен для скачивания. Автоматического платного конвертера нет.
5. При публикации админка проверяет тип, размер и доступность через API диска. Выберите фактический формат: PNG-ссылка при выбранном PDF должна дать предупреждение. Максимальный размер — 100 МБ.

В приложении: «Материалы» → категория → страна (если есть региональные документы). Общие документы показываются при любом выбранном регионе. Язык интерфейса не выбирает страну. Пустые региональные кнопки не выводятся. Скрытие и редактирование приходят через существующие подписки Firestore после публикации, без новой сборки для каждого документа.

PDF и изображения скачиваются во временный частный кэш и открываются локально. «Скачать» сохраняет оригинал через системное окно Android или «Файлы» iOS. Сохранённый пользовательский файл остаётся на устройстве для открытия без интернета; сам каталог приложения продолжает использовать существующую модель доступа. Для Office без PDF предлагается скачивание или явная кнопка открытия на диске. Браузер автоматически не запускается.

Файлы остаются на дисках; Firebase хранит только каталог, ссылки и метаданные. **Публичную ссылку сможет открыть любой, кто её получил. Промокод не защищает сам облачный файл.** Не используйте такой доступ для конфиденциальных документов.

Категорию с документами удалить нельзя, включая черновики. Сначала отдельно перенесите или удалите документы. Добавление, перенос, удаление документа и изменение счётчиков выполняются атомарно; устаревший редактор или повторное удаление получают конфликт. Файлы на облачном диске эти действия не удаляют.

Ранее добавленные ссылки сохранены в раскрывающемся блоке «Ранее добавленные материалы». Они продолжают работать по старому контракту; старые произвольные HTTPS-ссылки не превращаются автоматически в новые документы с нативным скачиванием.

## Если Google Диск сообщает об API

Для Google используется официальный Drive API v3. По умолчанию берётся существующий публичный API key Firebase соответствующей платформы. В Google Cloud Console того же проекта проверьте, что **Google Drive API включён**, а ограничения ключа допускают Drive API. Не удаляйте ограничения других Firebase API и не меняйте Firebase Auth ради материалов.

Если существующий ключ по своим ограничениям не подходит, можно указать отдельный **публичный клиентский** ключ Drive API:

- админка: `config/materials-config.js`, поле `googleApiKey`;
- Android: `app/src/main/res/values/materials_config.xml`, строка `ff_drive_api_key`;
- iOS: `FaberlicForever/Info.plist`, поле `FFGoogleDriveAPIKey`.

Пустое значение использует прежний Firebase key. Настройки выполняет владелец. Секретные OAuth-токены, serviceAccount и административные ключи туда добавлять нельзя. Для публичного Яндекс Диска отдельный ключ не нужен. HTML-страницы диска не парсятся, временные ссылки скачивания не сохраняются в Firestore.

## Иконки уроков и плеер

В форме урока появился режим иконки: «Автоматически по теме» или ручной выбор из встроенной библиотеки. Автоматически проверяются название, описание, иконка подраздела/категории, затем стандартная иконка видео. Ручной выбор не меняется при смене заголовка. Старые уроки работают без массовой перезаписи.

Иконка заменяет миниатюру только в списке уроков категории. YouTube-обложки на главной, баннеры и история сохранены. Плеер сохраняет предыдущую реализацию: Auto/9:16/16:9/1:1, пропорции без CSS-обрезки видео, поворот и полноэкранный выход. Auto не выдумывает исходные размеры по Shorts, длительности или обложке. Подробности ограничений YouTube — в `ADAPTIVE_PLAYER_RU.md`.

## Сборка приложений

**Android:** откройте `2_ANDROID_PROJECT` в Android Studio, дождитесь Sync. Собирайте через Build → Generate Signed Bundle / APK. Для обновления поверх установленного приложения нужны **прежний applicationId и тот же ключ подписи**, с которым оно было установлено. Версия повышена до 22; если установленная у вас сборка имеет больший versionCode, увеличьте его дополнительно. Чужой или тестовый ключ несовместим с вашей установленной версией. В комплекте намеренно нет APK и ключей; подробности в `OPEN_ANDROID_STUDIO_RU.txt`.

**iOS:** откройте `3_IOS_XCODE_PROJECT/FaberlicForever.xcodeproj` на Mac, добавьте ваш настоящий `GoogleService-Info.plist` в `FaberlicForever`, проверьте Bundle ID и Signing Team, дождитесь загрузки Firebase SDK и соберите в Xcode. В предоставленном исходнике был только `.example`; ваш настоящий конфиг и подпись не подменялись.

Android собран локально с временным тестовым ключом для проверки компиляции. iOS проверен статически и в браузерных тестах общих экранов, **не собран в Xcode и не проверен на iPhone**. Нативные просмотрщики и системное сохранение на физических Android/iOS требуют проверки владельцем перед выпуском. Сохраняется ранее описанный риск HTTP Referer локального YouTube iframe на iOS; это не подтверждённый тест воспроизведения на устройстве.

Это проверка API и файла на Windows; не доказательство работы нативного экрана на телефоне. Перед выпуском проверьте на своих телефонах: PDF/JPG Google, PDF Яндекс, PPTX Яндекс + PDF-копия; сохранённый файл без интернета; закрытую/удалённую ссылку; лимит; отмену; поворот и возврат из плеера. Рабочие документы для этих проверок удалять не нужно.
