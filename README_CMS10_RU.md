# Faberlic Forever Admin — CMS-10: Эфиры и Материалы

Основа: **Faberlic_Forever_Admin_CMS08_P0_P1_FIXED_FULL.zip** (архив исправлений Codex). Не смешивать с самостоятельной CMS-09 или старой CMS-08 без аудита различий.

## Добавлено

- **Эфиры:** название, YouTube-ссылка (включая Shorts/live), ведущий, дата и время, язык RU/TJ/UZ, состояние «Запланирован» / «В эфире» / «Запись», черновик/публикация, описание, список, редактирование, удаление. Статус «В эфире» **ручной**; автоматического опроса YouTube API нет.
- **Материалы:** название, описание, тип (чек-лист / документ / презентация / инструкция / ссылка), язык, статус черновика/публикации, безопасная HTTPS-ссылка, редактирование и удаление.
- **Файлы:** документ/презентацию сначала нужно разместить в Яндекс Диске, Google Drive или другом доступном внешнем хранилище и вставить ссылку. **Прямая загрузка PDF-файла из админки не реализована**, потому что в текущем проекте на Firebase Spark нет безопасно настроенного файлового хранилища. Не путать эту функцию с загрузкой бинарных файлов.
- Данные записываются в новые коллекции `liveStreams` и `materials`. Хранение видео остаётся в YouTube; Firestore хранит только поля и ссылки.
- Для редактирования используется номер редакции документа в транзакциях, чтобы не затирать случайно изменения другой вкладки.

## Совместимость и ограничения

- Не изменены `videos.js`, `categories.js`, `ranks.js`, базовые цвета, лого, навигация и формы уроков.
- В базу `firebase.js` добавлены методы `listContent`, `saveContent`, `deleteContent` и точная диагностика отказа чтения `lessonOrderScopes`; прежние транзакции видео сохранены.
- В `repository.js` сохранена причина ошибки загрузки для формы урока, чтобы вместо бесполезного «обновите страницу» отображался код отказа Firebase.
- В `firestore.rules` **предложены** правила для `materials` и `liveStreams` поверх текущего комплекта Codex. Они не развернуты. Не публиковать не проверив в Emulator Suite и не сохранив резервную копию текущих Rules.
- Приложение Android должно быть обновлено до версии из комплекта CMS-10, иначе его старые пустые разделы не будут читать новые коллекции.
- Проблема `dataReady=false` из более ранней версии Codex может сохраняться, если действующие Rules не включают `lessonOrderScopes`; данное расширение её не маскирует.
- Это автономное тестирование без действующей Firebase, Google Play и Android SDK. Полноценная приёмка требует проверки на реальном Firebase и телефоне.

## Безопасный порядок внедрения

1. Сделать резервную копию опубликованных Firestore Rules; согласовать и проверить обновлённый `firestore.rules` (включая прежние правила `lessonOrderScopes`) в Firebase Emulator Suite.
2. Опубликовать **проверенные** правила и убедиться, что старые уроки и `taxonomy/catalog` читаются как прежде.
3. Обновить файлы из CMS-10 PATCH на GitHub Pages, сохраняя точную структуру папок.
4. После загрузки страницы с очисткой кэша создать черновик материала/эфира; проверить, что не отображается на телефоне. Затем опубликовать его.
5. Собрать Android APK и проверить списки RU/TJ/UZ, открытие YouTube, переход к документам во внешний браузер.

Для воспроизводимости статических проверок: `node --check assets/js/modules/live.js`, `node --check assets/js/modules/materials.js`, `node tests/test_content_cms10.cjs` (не заменяет эмулятор Firebase).
