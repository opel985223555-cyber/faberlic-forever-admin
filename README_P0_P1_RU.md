# CMS-08: первый этап P0/P1

Этот полный комплект подготовлен из `Faberlic_Forever_Admin_CMS08_FULL.zip`. Исторические README сохранены; для текущего этапа используйте этот файл и `FIX_REPORT_P0_P1_RU.md`.

**Ничего не опубликовано. Новые Firestore Rules — проект для проверки, а не уже действующие правила.** Старые правила запрещают новую служебную коллекцию, поэтому исправленная панель с ними блокирует запись при загрузке данных. Перед будущим разрешённым развёртыванием требуется проверка Rules в локальном Emulator Suite и согласованное обновление панели и правил. Старые вкладки администраторов нужно закрыть. Android-чтение опубликованных уроков и каталога сохраняется по схеме Rules.

## Контракт данных

- `/taxonomy/catalog` сохраняет `items`, `version:1`, `updatedAt` и дополнительные существующие поля. Добавляется `revision`; отсутствующая редакция старого документа считается 0. Транзакция проверяет редакцию и наличие документа, валидирует дерево и запрещает удаление существующих ID. При конфликте никаких изменений не записывается.
- Уроки остаются в `/lessons/{id}`. Существующие ID, `createdAt` и неизвестные дополнительные поля сохраняются. Новые служебные поля: `revision`, `orderScopeId`, `orderRevision`; для новых уроков также `clientRequestId`. Старые документы не переписываются при загрузке. Отсутствующая lesson revision считается 0, `leafCategoryId` восстанавливается в логике чтения по существующей legacy-схеме.
- `/lessonOrderScopes/{leafCategoryId}~{language}` — новая служебная коллекция с `leafCategoryId`, `language`, `revision`, `updatedAt`. Она доступна только администраторам. Все операции добавления, изменения, переноса, удаления и сортировки используют её транзакционную редакцию. Никакого предварительного массового заполнения коллекции не требуется: нужный документ создаётся при первом изменении соответствующей области.
- Все чтения перед подготовкой записи требуют ответа сервера. Ошибка чтения/валидации блокирует запись, а не подменяет каталог исходным seed.
- Корень имеет глубину 0; допускаются уровни до 20 включительно. Циклы, сироты, повторные ID, некорректные типы, статусы и превышение глубины запрещены. Перенос проверяет глубину всего поддерева.
- Данные без обязательного названия, корректного YouTube ID, статуса или действительной категории считаются повреждёнными. Они не удаляются, не исправляются автоматически и не исключаются молча; запись блокируется до отдельного разбора. Существующий неизвестный version каталога также не перезаписывается.

## Конфликт и повтор сохранения

При конфликте появляется сообщение о другом администраторе. Нужно обновить страницу, проверить актуальные данные и повторить действие. Автоматическое слияние не выполняется. Последовательные новые уроки получают серверно рассчитанный `max+1` в своей категории и языке; перестановка проверяет полный состав области и редакции документов.

Для нового урока ID выделяется до транзакции и используется повторно после неопределённого результата. Токен хранится в памяти и `sessionStorage` этой вкладки, отдельно для проекта и пользователя. Если хранилище недоступно, остаётся защита повторов в текущей странице; устойчивость токена после перезагрузки без sessionStorage не гарантируется.

При потере подтверждения commit повторите исходное сохранение. Обновление списка не забывает токен. Если урок уже появился в списке, можно открыть именно его для редактирования и сохранить — это подтвердит исходную операцию. Пока результат не определён, попытка создать другой урок с изменёнными полями блокируется. Не очищайте sessionStorage и не начинайте «повтор» в новой вкладке: это уже отдельный запрос.

После подтверждённой записи форма очищается до обновления списка. Ошибка чтения сообщает «Урок сохранён, но список не обновлён», и дальнейшая запись блокируется до успешной загрузки.

Для безопасности этого этапа перестановка ограничена 400 уроками; сохранение/перенос — 400 уроками в сумме затронутых областей, перенос категории — 100 узлами затронутого поддерева. Каталог ограничен 1000 узлами. Превышение останавливает операцию без изменений, а не делит её на частичные записи. Большие объёмы требуют отдельного решения и проверки лимитов Firestore.

## Что проверено

`node tests/test_p0_p1.cjs` — 30 пройденных проверок на полном настоящем HTML/JS/CSS в Edge с двумя независимыми браузерными контекстами и общей локальной моделью optimistic/MVCC-транзакций. Все внешние запросы перехвачены; SDK заменён тестовой реализацией. Проверяется **настоящий исправленный адаптер**, а не подменённый `repo.save`. Это не Firebase Emulator и не проверка Security Rules.

Запуск требует уже установленного Node Playwright. Можно задать `NODE_PATH` или `FF_PLAYWRIGHT_MODULE`, а также `FF_BROWSER_PATH`. В Windows по умолчанию используется установленный Edge. Новые зависимости при подготовке комплекта не устанавливались.

Синтаксис всех JS/CJS проверен `node --check`. Статический Python-тест YouTube-only пройден. Исходные Python UI-тесты в данной среде не запустились из-за отсутствующего Python Playwright. Основные регрессионные сценарии выполнены новым Node-тестом. В старом тесте админки адаптирован только mock нового метода чтения snapshot.

Для проверки неизменных модулей:

```text
python tests/verify_module_lock.py --allow index.html --allow assets/js/core/firebase.js --allow assets/js/core/repository.js --allow assets/js/modules/categories.js --allow assets/js/modules/videos.js --allow firestore.rules
node tests/verify_change_scope.cjs
```

Исходный `LOCKED_MODULES.json` сохранён: старые контрольные суммы не подменены. Дополнительно `P0_P1_CHANGESET.json` содержит исходные и итоговые SHA-256, список изменений и новых файлов.

## Подготовленные серверные проверки

`tests/test_firestore_rules.cjs` содержит 10 сценариев Rules для **локального** Firestore Emulator: публичное чтение, черновики, неадминистраторы, миграция старых редакций, неправильные типы, устаревшие записи, привязка к области порядка, атомарность отказа и удаление с редакцией. Эти 10 сценариев **не выполнены**: нет Firebase CLI, emulator JAR и пакетов `firebase` / `@firebase/rules-unit-testing`.

Если эти инструменты уже установлены, локальный запуск:

```text
firebase emulators:exec --only firestore --project demo-ff-cms08-p1 "node tests/test_firestore_rules.cjs"
```

Тест запрещает запуск без явного localhost `FIRESTORE_EMULATOR_HOST`; проект имеет префикс `demo-`. В комплекте нет автоматического deploy-скрипта.

Rules валидируют верхний уровень catalog, типы уроков, права и транзакционные редакции. Проверка всех узлов произвольного дерева и запрет замены существующего ID другим ID при одинаковом размере выполняются в клиентской транзакции; Rules сами по себе не дают полной проверки произвольного графа. Администратор с прямым доступом Console/Admin SDK остаётся доверенным оператором. Все веб-писатели должны использовать этот протокол; совместимость произвольного старого писателя не обещается.

Не проверены реальный Firebase/CDN, компиляция и выполнение Rules, SDK на настоящем эмуляторе, рабочий Android и нагрузочные лимиты. До этой проверки комплект нельзя считать готовым к производственной публикации.
