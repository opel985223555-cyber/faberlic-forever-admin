# Faberlic Forever CMS-11 — удаление категорий

Добавлена кнопка «Удалить» рядом с «Изменить». Перед удалением показывается название категории. Категория с видео любого языка или статуса не удаляется. Категория с дочерними категориями не удаляется, даже если они пустые: сначала перенесите или удалите дочерние категории. Пустую вложенную категорию удалить можно. Видео автоматически не удаляются.

## Что заменить на GitHub

Распакуйте архив CHANGED_FILES в корень проекта с сохранением путей; это все изменения поверх предоставленного CMS-10. Или используйте полный архив FULL. Файлы находятся сразу в корне ZIP, без дополнительной папки. config/firebase-config.js в обновлении не изменён. Пользовательские секреты и ключи сервисных аккаунтов не добавлялись.

Основные заменяемые файлы:
- assets/js/modules/categories.js — кнопка, подтверждение, предупреждения, обновление списка;
- assets/js/core/firebase.js — вызов серверной функции, блокировка конкурентных привязок видео;
- assets/js/core/repository.js — подготовка служебного индекса при первом сохранении видео;
- index.html — только версии кеша трёх изменённых скриптов;
- firestore.rules и firebase.json;
- новая папка functions/ — обязательная серверная часть;
- firebase.emulator.json, tests/test_cms11_*.cjs и отчёты — локальные тесты;
- README_CMS11_RU.md и CHANGESET_CMS11.json — инструкция и перечень изменений.

Стили, изображения, авторизация и исходные модули videos.js, live.js, materials.js не изменены. Общий слой Firebase меняется только для безопасной работы категорий и привязок уроков. RU/TJ/UZ сохранены.

## Что сделать в Firebase

Одной замены файлов GitHub и правил НЕДОСТАТОЧНО: нужна callable Cloud Function cms11Catalog (регион us-central1). Изменения каталога, включая добавление, редактирование и порядок, проходят её проверку. Без развёрнутой функции сохранение категорий недоступно. Cloud Functions требует тариф Blaze; подключение тарифа и публикацию выполняет владелец проекта. См. https://firebase.google.com/docs/functions/get-started и https://firebase.google.com/docs/functions/manage-functions .

1. Запланируйте короткое окно обновления: закройте старые вкладки CMS у всех администраторов. Сохраните резервную копию файлов и данных средствами вашего проекта.
2. Установите Node.js 22 и Firebase CLI, авторизуйтесь через firebase login. Все следующие команды предназначены ДЛЯ ВАС; при подготовке архива они не выполнялись.
3. Из корня распакованного проекта установите зависимости функции и опубликуйте только отдельную codebase cms11:

   cd functions
   npm ci
   cd ..
   firebase deploy --only functions:cms11 --project ВАШ_PROJECT_ID

   ВАШ_PROJECT_ID — projectId из config/firebase-config.js. Если уже есть серверные функции в другом рабочем каталоге, объедините соответствующие конфигурации firebase.json, сохранив их codebase. Не используйте команду общего развёртывания всех функций.
4. Откройте Firebase Console → Firestore Database → Rules. Полностью замените правила содержимым firestore.rules (или отдельного файла Firestore_CMS11_RULES.txt) и нажмите Publish. Альтернатива из корня проекта:

   firebase deploy --only firestore:rules --project ВАШ_PROJECT_ID

5. Загрузите обновлённые файлы сайта на GitHub своим обычным способом. После обновления откройте CMS с принудительной перезагрузкой Ctrl+F5 и войдите как администратор.
6. При первом сохранении категории сервер автоматически сохранит карту привязок roots и документ catalogGuards/membership. При первом сохранении видео на старом каталоге подготовка выполняется автоматически. Существующие документы lessons не мигрируются и не удаляются. Если в исходной базе уже есть некорректная привязка видео, сервер остановит изменение и сообщит ID видео; исправьте привязку через обычную форму видео.
7. Для проверки создайте отдельную временную пустую категорию и удалите только её. Производственные категории специально для проверки удалять не нужно.

Старые открытые клиенты CMS-10 после смены правил не смогут писать каталог и создавать видео без новой блокировки; им нужно обновить страницу. При конфликте обновите список/страницу и повторите осознанное действие. Откат требует согласованного восстановления фронтенда и правил; старый фронтенд отдельно с новыми правилами несовместим.

## Как обеспечена безопасность

Правила Firestore не могут выполнить запрос «нет ни одного урока этой категории». Поэтому прежняя проверка размера массива заменена запретом прямой клиентской записи каталога. Записывать его может только функция с Admin SDK, которая повторно проверяет admins/{uid}. Метод putCatalog() вызывает эту функцию вместо прежнего абсолютного запрета удаления ID.

Сервер в транзакции проверяет редакцию каталога, дерево и все актуальные lessons, включая старые categoryId/topicId и новые leafCategoryId. Он сохраняет все поля существующего каталога и строит карту roots. Создание и перенос видео, а также изменение каталога атомарно увеличивают catalogGuards/membership. Правила требуют общую блокировку и существующую корректную привязку при создании/переносе видео. Это закрывает гонку между проверкой пустоты и новым видео. Несвязанные видео по-прежнему используют прежние блокировки порядка.

Прямые записи через Admin SDK, консоль Firebase или сторонний привилегированный импорт обходят Security Rules по устройству Firebase. Если у вас есть другие серверные писатели lessons/taxonomy, им нужно использовать тот же протокол блокировки; данный ZIP содержит только писателей исходного веб-проекта. Публичное чтение каталога и опубликованных видео сохранено.

Сервер при изменении каталога читает всю коллекцию lessons: это надёжно учитывает старые форматы без опасной миграции счётчиков, но создаёт расходы на чтения. При очень большой коллекции возможен тайм-аут: операция завершится ошибкой без частичного изменения.

## Проверки и повторный запуск

Браузерные тесты используют полный интерфейс и подменённые SDK/данные; эмуляторные тесты используют настоящий Firestore SDK, правила и серверный обработчик. Ни один тест не обращается к рабочей базе.

Для локального запуска установите тестовые зависимости ВНЕ публикуемой папки functions, например в отдельный каталог; задайте NODE_PATH на его node_modules:

   npm install firebase @firebase/rules-unit-testing firebase-tools firebase-admin playwright
   node tests/test_cms11_browser.cjs
   firebase emulators:exec --config firebase.emulator.json --only firestore --project demo-ff-cms11 "node tests/test_cms11_emulator.cjs"
   node tests/test_content_cms10.cjs
   python tests/test_youtube_only_policy.py
   python tests/verify_module_lock.py --allow index.html --allow assets/js/core/firebase.js --allow assets/js/core/repository.js --allow assets/js/modules/categories.js --allow firestore.rules

Для браузерного теста в Windows используется установленный Edge; для другой ОС задайте FF_BROWSER_PATH. Для актуального Firebase CLI требуется Java 21+. При подготовке проверен также Firebase CLI 13.35.1 с Firestore emulator 1.19.8. Сохранённые CMS-10 тесты не переписаны: старый test_firestore_rules.cjs специально ожидает прежнюю модель запретов, поэтому для CMS-11 используйте test_cms11_emulator.cjs; test_p0_p1.cjs заменён в текущем прогоне расширенной копией test_cms11_browser.cjs.

Отчёты текущего прогона: tests/CMS11_BROWSER_RESULTS.json и tests/CMS11_EMULATOR_RESULTS.json. Исторические отчёты CMS-10 остаются историческими.

GitHub, Firebase production и ветка main при подготовке не изменялись. Развёртывание в облаке и работа с вашим реальным проектом не проверялись. Локальная среда: Node.js 24; production runtime функции задан Node.js 22.
