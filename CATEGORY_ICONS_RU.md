# Иконки категорий Faberlic Forever

Обновление 25 октября 2026. Подготовлено на последней версии из этой переписки, включая промокоды/групповые выдачи, мобильную админку и выбор языка.

## Что сделано

В админке в форме категории появилось поле «Иконка категории» и кнопка «Выбрать иконку». Один переиспользуемый компонент IconPicker открывает встроенную библиотеку из **80 значков**: 72 новых варианта по всем пунктам задания и 8 прежних значков проекта. Instagram, TikTok, Telegram, WhatsApp, YouTube и Facebook используют свои фирменные SVG из Simple Icons; обычные — Lucide.

Есть поиск по русскому названию, английскому ID/бренду и ключевым словам (ё/е не мешают поиску), темы, подсветка выбранного значка, «Применить» и отмена/Escape. В настольном окне шесть колонок; на 390 px — четыре, на 320 px — три. До «Применить» форма не изменяется, до сохранения категории Firebase не изменяется.

Выбор отображается в форме и в списке категорий. Android и iOS используют тот же реестр ID для корневых и вложенных категорий. Старые значки сохранены, старые числовые обозначения уровней без выбранной иконки остаются; у остальных категорий без значка/с неизвестным ID показывается безопасная стандартная папка. Размеры строк и существующий плеер/навигация/шрифты не изменялись.

## Данные и миграции

Фактический проект использует **Firebase Firestore**, а не Supabase. Каталог хранится в `taxonomy/catalog`, категории — в массиве `items`. Поле `icon` уже существовало у части категорий: оно использовано без новой схемы.

Примеры сохранённых значений: `brand:instagram`, `brand:telegram`, `brand:tiktok`, `lucide:users`, `lucide:graduation-cap`, `lucide:shopping-cart`. Ключи не зависят от языка. Старые короткие ключи (`spark`, `bars`, `users`, `diamond`, `heart`, `screen`, `trophy`, `team`) поддерживаются без массовой перезаписи.

**Миграция Supabase не нужна. Правила Firebase для этой доработки не менялись.** Никаких загрузок в Storage, файлов изображений на категорию, React-пакетов или CDN нет. Реестр около 31 КБ до сжатия, работает локально. Сохранение идёт через существующие транзакции каталога с общей ревизией: устаревшее редактирование не затирает новое, видео не перемещаются и не удаляются.

## Как обновить и пользоваться

1. Админка: замените файлы сайта из ZIP админки с сохранением путей. Дождитесь GitHub Pages deployment и обновите страницу Ctrl+F5. Метки новых файлов `icons17` предотвращают загрузку старого модуля категорий.
2. Откройте «Категории» → добавление или «Изменить» → «Выбрать иконку» → найдите/выберите значок → «Применить» → «Добавить раздел»/«Сохранить изменения».
3. Перезагрузите страницу: иконка останется. Для замены откройте ту же форму ещё раз.
4. Для новых значков в мобильных приложениях соберите Android и iOS из соответствующих полных ZIP. Одного обновления админки недостаточно, чтобы старая установленная версия приложения узнала новые значки. Старое приложение продолжит работать со своим запасным значком.

Для этой функции не требуется заново включать Anonymous, пересоздавать категории/промокоды или менять правила. Предыдущие настройки Firebase для активации и учёта выдач должны оставаться действующими.

## Проверки и ограничения

* **59/59** браузерных сценариев админки: предыдущие функции плюс реестр из 80 уникальных ID/шесть разных брендовых SVG, создание Instagram-категории через picker, сохранение и полная перезагрузка страницы, замена на Telegram, сохранение TJ/UZ, отмена/Escape, пустой поиск, поиск «кошелек» без ё, старые/неизвестные иконки, выбор на 1280/390/320 px.
* **30/30** браузерных сценариев Android/iOS Web-частей: прежние функции плюс брендовые/старые/запасные значки, корневые и вложенные категории, переключение RU/TJ/UZ. Тестовый native bridge, без запуска физических устройств.
* **23/23** группы интеграции каталога через реальный Firebase SDK и Firestore Rules на локальном эмуляторе: включены сохранение/read/edit поля icon после повторного чтения, переводы, существующий урок и конфликт параллельного редактирования. Остались проверки удаления/скрытия/закрытия и гонок с уроками.
* JavaScript `node --check`: 22 runtime-файла админки, по 19 Android/iOS. SVG-источники разобраны XML-парсером, все 72 сопоставления найдены в фиксированных пакетах библиотек.
* Android: `assembleDebug` и `bundleRelease` — BUILD SUCCESSFUL после изменений. Полученный release bundle неподписан; в ZIP только исходники, бинарники/ключи подписи не включены.
* iOS: проверены Swift-грамматика, plist, ссылки проекта. Native iOS не компилировался на Windows, нужны Mac/Xcode и настоящий GoogleService-Info.plist, отсутствовавший в исходном архиве. Реальная клавиатура/Safari/устройства в этой задаче не запускались.
* ZIP проверены по CRC; защита, видео, материалы, промокоды, правила и native-модули сверены с предыдущими ZIP и сохранены побайтно.

Рабочая Firebase не использовалась для тестовых записей. На GitHub/Firebase ничего не опубликовано, main не менялась.

## Изменённые runtime-файлы

Админка:

* `index.html` — поле формы, подключение модулей/CSS.
* `assets/js/modules/categories.js` — предпросмотр, редактирование/сохранение icon и значок в строке.
* `assets/js/core/category-icons.js` — новый единый реестр SVG и безопасный fallback.
* `assets/js/core/icon-picker.js` — новый переиспользуемый IconPicker.
* `assets/css/icon-picker.css` — новый стиль поля, SVG и адаптивного окна.

Android, относительно `app/src/main/assets/www/`, и iOS, относительно `FaberlicForever/Web/`:

* `index.html` — подключение реестра/CSS.
* `core/category-icons.js` — тот же реестр, побайтно идентичный админке.
* `modules/categories-cms.js` — отображение ID из данных в существующих строках категорий.
* `modules/category-icons.css` — размер/заливка/обводка SVG, без изменения геометрии экрана.

Также добавлены тексты лицензий, карта ID, тесты и отчёты в `licenses/` и `verification/`. Машинный список отличий относительно предыдущих ZIP — `verification/ICON_CHANGESET.json`.
