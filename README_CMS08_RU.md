# CMS-08 — исправления относительно CMS-07

Изменения выполнялись в существующих блоках редактирования контента, без переработки дизайна, авторизации, фирменной графики, зафиксированных разделов «Эфиры»/«Материалы» и Android-приложения.

## Исправлено

1. **Публикация на GitHub:** исправлен неполный патч прошлой версии. Новый `CMS08_GITHUB_FROM_V04_PATCH.zip` сформирован сравнением с фактической исходной админ-панелью v04 — содержит все необходимые новые/изменённые файлы и папки.
2. **Загрузка обновления:** в `index.html` добавлено версионирование ссылок JS/CSS, чтобы браузер не продолжал показывать старые формы после замены файлов на GitHub.
3. **Скрытые категории:** остаются доступны в административном списке выбора, с явной пометкой `[Скрыт]`. Редактирование видео в таком разделе не обнуляет категорию.
4. **Перенос заполненных разделов:** заблокирован при наличии связанных уроков, предотвращает неверные ссылки на вложенные темы. Переименование, описание, статус и порядок менять можно.
5. **Перенос пустых разделов:** исправлены номера порядка среди старых и новых соседей. Родитель проверяется на существование, циклы не допускаются.
6. **Новые категории:** удобный иерархический список с метками «Скрыт»/«Скоро». Пустые открытые разделы в списке отмечены как «Скоро · нет опубликованных уроков».
7. **Сохранение урока:** добавлена явная проверка существования выбранной категории и исходного редактируемого урока.
8. **Параллельные действия:** повторная запись/перестановка не запускаются одновременно с другой выполняющейся операцией.
9. **Обложки:** по-прежнему только YouTube; собственные файлы и Firebase Storage не используются.

## Выполненные тесты

- Браузерный UI-тест на Chromium без сетевого доступа с подменой Firestore: вход без авторизации закрыт, сохранение, категории, RU, вложенность, статус, защита от переноса, порядок уроков, изменение скрытой категории и мобильное меню.
- Корректные URL YouTube: `watch`, `youtu.be`, `shorts`, `live`; поддельный домен отклоняется.
- Статическая политика YouTube-only, проверка всех JS-файлов (`node --check`), проверка контрольных сумм зафиксированных модулей (`verify_module_lock.py`).

## Необходимо подтвердить на рабочем Firebase

Обновление правил вручную, публикация структуры, создание и сохранение пробного черновика, синхронизация категорий и перестановки в Android. Среда теста не содержит административного входа в рабочий Firebase; проверку на настоящем телефоне и живом сайте нельзя считать выполненной.
